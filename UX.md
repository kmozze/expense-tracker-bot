# План UX

> Статус на 2026-06-02: это продуктовый план. В коде уже реализованы `/start`, `/menu`, главное меню, сценарий добавления расхода, редактирование расхода, удаление расхода из сохраненной карточки и список расходов. Пользовательские диалоги идут через новые сообщения и reply-клавиатуру, а главное меню, список расходов и действия с уже сохраненными карточками идут через inline-кнопки. Управление категориями и статистика пока остаются планом.

### 0. Общие UX-правила

**Пользовательский диалог** - сценарий, где бот ждет следующий ввод пользователя и хранит незавершенный контекст в `UserState`.

Примеры:
- добавление расхода;
- редактирование расхода;
- добавление и редактирование категории;
- сложное удаление категории с выбором "удалить вместе с расходами" или "перенести расходы".

Такие сценарии идут через новые сообщения и reply-клавиатуру. Старые сообщения не превращаются в следующий шаг диалога.

Reply-клавиатура используется только как временный ввод внутри активного диалога. После успешного завершения или отмены бот убирает reply-клавиатуру.

**Главное меню** - навигационный экран из двух сообщений:

```
🧭 Главное меню

/menu — открыть это меню в любой момент.
/start — запустить бота. Если категорий нет, будут созданы базовые.
```

```
Что хотите сделать?
[➕ Добавить расход]
[📋 Расходы]
[📂 Категории]
[📊 Статистика]
```

Команда `/menu` работает из любого состояния: сбрасывает текущий диалог, не сохраняет черновик и показывает главное меню. Команда `/start` тоже сбрасывает текущий диалог и остается onboarding/init-сценарием: создает базовые категории при первом запуске и затем показывает главное меню.

Если `/menu` вызван из активного диалога, первое сообщение главного меню убирает reply-клавиатуру. Отдельного технического сообщения вроде `Готово` при этом нет.

Inline-кнопки меню и карточек работают только когда пользователь не находится в активном диалоге. Если пользователь нажал callback не в том состоянии, бот не выполняет действие, не меняет `UserState` и отвечает callback alert-уведомлением: `Сначала завершите или отмените текущий диалог.`

Если один пользовательский ввод должен и убрать reply-клавиатуру, и показать сообщение с inline-кнопками, бот отправляет несколько сообщений. Например после успешного сохранения или обновления расхода: сначала короткое `✅ Сохранено!` с удалением reply-клавиатуры, затем нейтральную карточку сохраненного расхода с inline-действиями.

**Карточка сохраненной сущности** - сообщение про уже сохраненный расход или категорию. Inline-кнопки под карточкой относятся только к этой карточке и этому сообщению.

Примеры:
- открыть расход из списка;
- открыть категорию из списка;
- удалить конкретный расход;
- начать редактирование конкретного расхода или категории.

Если inline-действие запускает длинный диалог, исходная карточка становится неактивной: у нее убираются inline-кнопки, но текст карточки остается нейтральным. Следующий шаг диалога бот отправляет отдельным сообщением ниже. После успешного действия или отмены бот отправляет новую актуальную карточку.

**Списки** - snapshot на момент построения. Список не обязан автоматически обновляться после редактирования или удаления элемента. Для MVP действия из списка открывают отдельную актуальную карточку, а не редактируют сам список.

**Подтверждение удаления** - не popup. Telegram callback alert можно использовать только для уведомлений, потому что в нем нет выбора `Да` / `Нет`. Удаление подтверждается inline-кнопками в сообщении.

### 1. /start
Если у пользователя ещё нет категорий, создаются базовые категории (Еда, Транспорт, Жильё, Развлечения, Прочее) и появляется приветственное сообщение:

```
👋 Добро пожаловать! Я создал для тебя базовые категории расходов.
```

Если категории уже существуют, бот отправляет:

```
С возвращением! 💸 Я готов записывать твои новые траты.
```

Затем открывается главное меню

**Реализация сейчас:** `/start` очищает текущий диалог, убирает reply-клавиатуру первым ответом, отправляет `WelcomeFirstTime` или `WelcomeBack`, затем отдельное сообщение `Главное меню` с inline-кнопками.

### 2. Главное меню (Inline Keyboard)
При `/menu` бот отправляет два сообщения: информационное сообщение главного меню и отдельное сообщение с inline-кнопками:

```
🧭 Главное меню

/menu — открыть это меню в любой момент.
/start — запустить бота. Если категорий нет, будут созданы базовые.
```

```
Что хотите сделать?
➕ Добавить расход
📋 Расходы
📂 Категории
📊 Статистика
```

При `/start` бот сначала отправляет приветственное сообщение, затем показывает короткое сообщение `Главное меню` с inline-кнопками.

Кнопки меню запускают соответствующие действия только из базового состояния. Во время активного диалога они не прерывают текущую ветку; пользователь может выйти через `/menu` или кнопку `❌ Отмена`, если она есть в текущем диалоге.

### 3. Управление категориями

**Команда/кнопка:** `📂 Категории`

**Статус:** пока не реализовано в продукте. Сейчас кнопка отвечает сообщением, что раздел в работе.

Список категорий - snapshot. В MVP из списка открывается отдельная карточка категории.
Каждая категория в списке - отдельная inline-кнопка.

```
📂 Категории

[Еда и напитки]
[Транспорт]
[Жильё]

[➕ Добавить категорию]
```

Если категорий много, список получает пагинацию по тем же правилам, что и список расходов.

**Добавление категории:**
1. Бот отправляет новое сообщение: `Введите название категории`.
2. Пользователь вводит название.
3. Бот создает категорию и отправляет карточку новой категории.

Название категории уникально в рамках пользователя.

**Карточка категории:**

```
📂 Еда и напитки

[✏️ Редактировать] [🗑️ Удалить]
```

**Редактирование категории:**
1. Исходная карточка становится неактивной.
2. Бот отправляет новое сообщение: `Введите новое название категории`.
3. После успешного изменения бот отправляет новую актуальную карточку категории.

**Логика удаления:**
1. Проверяем есть ли траты в категории
2. Если **нет** трат → показываем inline-подтверждение на карточке категории и после подтверждения удаляем.
3. Если **есть** траты → бот запускает отдельный пользовательский диалог:

```
По категории «Еда и напитки» есть 12 трат на сумму 8450 ₽.

Что сделать?
[🗑️ Удалить категорию и все траты]
[🔄 Перенести траты в другую категорию]
[❌ Отмена]
```

Если выбран перенос, бот предлагает выбрать целевую категорию через reply-клавиатуру со всеми остальными категориями.

### 4. Добавление расхода (Свободный ввод)
Основной способ — ввод суммы одним сообщением. Описание можно добавить в том же сообщении; бот автоматически отделяет число от текста. Текст становится **описанием**, а категорию пользователь выбирает кнопкой.

**Статус:** поток добавления реализован по целевому UX: ввод суммы с опциональным описанием, выбор категории через reply-клавиатуру, выбор даты через reply-клавиатуру или ручной ввод, удаление reply-клавиатуры, отдельный статус `✅ Сохранено!` и отправка нейтральной карточки расхода с inline-действиями. Удаление расхода из карточки реализовано через inline-подтверждение под той же карточкой. Редактирование расхода из карточки реализовано для суммы, категории, даты и описания.

**Логика работы:**
1. **Ввод:** Пользователь пишет `500`, `500 такси` или `обед 450`.
2. **Выбор категории (Reply Keyboard):** Бот парсит сумму и опциональное описание, затем отправляет нейтральную карточку с уже понятными полями и отдельное сообщение `Куда запишем?` с reply-клавиатурой категорий пользователя. Если категорий нет, бот отвечает: `У вас нет ни одной категории. Создайте хотя бы одну, чтобы записывать расходы.` и возвращает пользователя в главное меню.

```
💰 Сумма: 500.00 ₽
📝 такси

Куда запишем?
Reply keyboard: [Еда] [Жильё] [Прочее] [Развлечения] [Транспорт] [❌ Отмена]
```

Если описания нет, строка `📝 ...` не показывается.

Категория выбирается по точному названию. Названия категорий уникальны в рамках пользователя. Если пользователь прислал текст, который не совпадает с категорией, бот отвечает `❌ Категория не найдена` и оставляет пользователя в выборе категории.

3. **Дата траты:** после выбора категории бот отправляет нейтральную карточку с суммой, категорией и описанием, затем отдельное сообщение и предлагает дату траты через reply-клавиатуру:
```
    💰 Сумма: 500.00 ₽
    📂 Категория: Транспорт
    📝 такси

    Когда была трата?
    Reply keyboard: [📅 Сегодня] [📅 Вчера] [✏️ Ввести дату вручную] [❌ Отмена]
```
Если выбран ручной ввод, бот снова показывает карточку с текущим контекстом и отдельным сообщением просит дату в формате `ДД.ММ.ГГГГ`. Отмена прекращает создание расхода.

4. **Результат:** После выбора даты расход сохраняется. Бот сначала отправляет короткое сообщение `✅ Сохранено!`, которое убирает reply-клавиатуру, затем отправляет отдельную нейтральную карточку:
```
    ✅ Сохранено!
```

```
    💰 Сумма: 500.00 ₽
    📂 Категория: Транспорт
    📅 Дата: 24.05.2026
    📝 такси
    [✏️ Изменить] [🗑️ Удалить]
```
Если описания нет, строка `📝 ...` не показывается.
5. При нажатии кнопок под сохраненным расходом:

**При [🗑️ Удалить]:** Бот сначала показывает подтверждение:
```
    💰 Сумма: 500.00 ₽
    📂 Категория: Транспорт
    📅 Дата: 24.05.2026
    📝 такси
    [🗑️ Да, удалить] [❌ Нет]
```
После подтверждения бот удаляет запись и заменяет сообщение на:
  `Расход удален`

**При [✏️ Изменить]:** Бот редактирует исходную карточку: убирает inline-кнопки, оставляет нейтральный текст карточки без дополнительного пояснения и отправляет новое сообщение:

```
    Что изменить?
    Reply keyboard: [✏️ Сумма] [📂 Категория] [📅 Дата] [✏️ Описание] [✅ Готово] [❌ Отмена]
```
6. Логика изменения конкретных полей:
* **[✏️ Сумма]:** Бот просит: `Введите новую сумму`.
    * Если введено число больше нуля: обновляет черновик редактирования, отправляет карточку черновика без inline-кнопок и снова предлагает выбрать поле.
    * Если введена ошибка: пишет `❌ Сумма должна быть числом больше нуля` и ждет повторный ввод.
* **[📂 Категория]:** Бот показывает reply-клавиатуру со всеми категориями. После выбора новой категории обновляет черновик и снова предлагает выбрать поле.
* **[📅 Дата]:** Бот предлагает быстрые варианты через reply-клавиатуру или ручной ввод. После выбора даты обновляет черновик и снова предлагает выбрать поле.
* **[✏️ Описание]:** Бот просит: `Введите новое описание`. Непустой присланный текст становится описанием в черновике, после чего бот снова предлагает выбрать поле.
* **[✅ Готово]:** Бот сохраняет накопленные изменения, отправляет `✅ Сохранено!` с удалением reply-клавиатуры и новую актуальную карточку расхода с inline-действиями.

**Общие правила:**
* Редактирование идет через черновик: до **[✅ Готово]** сохраненная запись в БД не меняется.
* Любое действие можно отменить кнопкой **[❌ Отмена]**; черновик отбрасывается.
* После каждой успешной правки бот отправляет карточку черновика без inline-кнопок и сообщение `Что изменить?` с reply-клавиатурой выбора поля.
* После отмены редактирования бот отправляет `Готово`, убирает reply-клавиатуру и отправляет текущую сохраненную карточку расхода без изменений из черновика.
* Старую карточку, с которой началось редактирование, не восстанавливаем.


### 5. Просмотр расходов + редактирование/удаление

**Кнопка:** `📋 Расходы`

**Статус:** реализовано в продукте.

Появляется меню настройки

```
Настройка отображения 📋

📅 Период: За месяц
📂 Категория: Все

[Изменить период 🗓] [Изменить категорию 📁]
[🔎 Показать список]
```

Дальше:

* **[Изменить период 🗓]:** Бот выводит список быстрых фильтров кнопками:
```
    Выберите период:
    [📅 День] [📅 Неделя] [📅 Месяц] [📅 Все время]
```
После выбора бот обновляет текст меню «Настройка отображения».

* **[Изменить категорию 📁]:** Бот выводит список всех категорий пользователя с дополнительным выбором всё:
```
    Выберите категорию для фильтра:
    [Все] [Еда] [Транспорт] ...
```
После выбора бот обновляет текст меню и фильтрует будущий список.

**Просмотр списка [🔎 Показать список]:**
После выбора бот отправляет список (максимум 10 записей на странице, с пагинацией при необходимости).
Каждый расход в списке - отдельная inline-кнопка:

```
📋 Расходы за неделю
Показано 1-4 из 4

[12.03 · Еда · 450 ₽]
[11.03 · Транспорт · 120 ₽]

[⬅️ Предыдущие] [Следующие ➡️]
```

Список - snapshot. Если расход был изменен или удален после построения списка, сам список не обновляется автоматически.

- **При нажатии строки расхода** бот заново загружает расход из БД и отправляет отдельную актуальную карточку с кнопками `[✏️ Изменить] [🗑️ Удалить]`.
- Если расход уже удален или недоступен, бот отвечает: `Расход уже удален или недоступен.`
- Редактирование и удаление дальше идут через карточку расхода по правилам из раздела 4.

Описание не показывается в строке списка. Если у расхода есть описание, оно показывается только после открытия полной карточки расхода.

Для MVP в списке нет прямых кнопок `Изменить` и `Удалить`, чтобы не поддерживать актуальность старого snapshot-сообщения.

### 6. Статистика

**Кнопка:** `📊 Статистика`

**Статус:** пока не реализовано в продукте. Сейчас кнопка отвечает сообщением, что раздел в работе.

Появляется стартовое меню

```
📊 Панель статистики

🗓 Период: Текущий месяц
📁 Категории: Все категории

[Изменить период 🗓] [Изменить категорию 📁]
[📝 Текстовая сводка]
```

Примеры вывода:

**Текстовая сводка:**
```
📊 За март 2026
Всего: 18 450 ₽

1. Еда и напитки — 8 200 ₽ · 44%
2. Транспорт — 3 900 ₽ · 21%
3. Жильё — 2 500 ₽ · 14%
...
```
