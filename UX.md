# План UX

> Статус на 2026-05-28: это продуктовый план. В коде уже реализованы `/start`, `/menu`, главное меню и базовый сценарий добавления расхода, но целевой UX добавления/редактирования пересмотрен: пользовательские диалоги идут через новые сообщения и reply-клавиатуру, а главное меню и действия с уже сохраненными карточками идут через inline-кнопки. Управление категориями, список расходов, статистика и редактирование расходов пока остаются планом.

### 0. Общие UX-правила

**Пользовательский диалог** - сценарий, где бот ждет следующий ввод пользователя и хранит незавершенный контекст в `UserState`.

Примеры:
- добавление расхода;
- редактирование расхода;
- добавление и редактирование категории;
- сложное удаление категории с выбором "удалить вместе с расходами" или "перенести расходы".

Такие сценарии идут через новые сообщения и reply-клавиатуру. Старые сообщения не превращаются в следующий шаг диалога.

Reply-клавиатура используется только как временный ввод внутри активного диалога. После успешного завершения или отмены бот убирает reply-клавиатуру.

**Главное меню** - навигационный экран из двух сообщений:

```
🧭 Главное меню

/menu — открыть это меню в любой момент.
/start — запустить бота. Если категорий нет, будут созданы базовые.

Что хотите сделать?
[➕ Добавить расход]
[📋 Расходы]
[📂 Категории]
[📊 Статистика]
```

Команда `/menu` работает из любого состояния: сбрасывает текущий диалог, не сохраняет черновик и показывает главное меню. Команда `/start` остается onboarding/init-сценарием: создает базовые категории при первом запуске и затем показывает главное меню.

Если `/menu` вызван из активного диалога, первое сообщение главного меню убирает reply-клавиатуру. Отдельного технического сообщения вроде `Готово` при этом нет.

Inline-кнопки меню и карточек работают только когда пользователь не находится в активном диалоге. Если пользователь нажал callback не в том состоянии, бот не выполняет действие, не меняет `UserState` и отвечает callback alert-уведомлением: `Сначала завершите или отмените текущий диалог.`

Если один пользовательский ввод должен и убрать reply-клавиатуру, и показать сообщение с inline-кнопками, бот отправляет несколько сообщений. Например после сохранения расхода: сначала короткое `Готово` с удалением reply-клавиатуры, затем карточку сохраненного расхода с inline-действиями.

**Карточка сохраненной сущности** - сообщение про уже сохраненный расход или категорию. Inline-кнопки под карточкой относятся только к этой карточке и этому сообщению.

Примеры:
- открыть расход из списка;
- открыть категорию из списка;
- удалить конкретный расход;
- начать редактирование конкретного расхода или категории.

Если inline-действие запускает длинный диалог, исходная карточка становится неактивной: у нее убираются inline-кнопки и текстом помечается, что действие продолжено ниже. После успешного действия или отмены бот отправляет новую актуальную карточку.

**Списки** - snapshot на момент построения. Список не обязан автоматически обновляться после редактирования или удаления элемента. Для MVP действия из списка открывают отдельную актуальную карточку, а не редактируют сам список.

**Подтверждение удаления** - не popup. Telegram callback alert можно использовать только для уведомлений, потому что в нем нет выбора `Да` / `Нет`. Удаление подтверждается inline-кнопками в сообщении.

### 1. /start
Если у пользователя ещё нет категорий, создаются базовые категории (Еда, Транспорт, Жильё, Развлечения, Прочее) и появляется сообщение

```✅ Созданы базовые категории для тебя!```

Затем открывается главное меню

**Реализация сейчас:** бот отправляет `WelcomeFirstTime` с текстом про созданные базовые категории или `WelcomeBack`, если категории уже существуют.

### 2. Главное меню (Inline Keyboard)
При `/menu` бот отправляет два сообщения: информационное сообщение главного меню и отдельное сообщение с inline-кнопками:
```
🧭 Главное меню

/menu — открыть это меню в любой момент.
/start — запустить бота. Если категорий нет, будут созданы базовые.

Что хотите сделать?
```

Inline-кнопки:
```
➕ Добавить расход
📋 Расходы
📂 Категории
📊 Статистика
```

При `/start` бот сначала отправляет onboarding/welcome-сообщение, затем показывает главное меню с inline-кнопками.

Кнопки меню запускают соответствующие действия только из базового состояния. Во время активного диалога они не прерывают текущую ветку; пользователь может выйти через `/menu` или кнопку `❌ Отмена`, если она есть в текущем диалоге.

### 3. Управление категориями

**Команда/кнопка:** `📂 Категории`

**Статус:** пока не реализовано в продукте. Сейчас кнопка отвечает сообщением, что раздел в работе.

Список категорий - snapshot. В MVP из списка открывается отдельная карточка категории.

```
📂 Категории

Еда и напитки
[Открыть]

Транспорт
[Открыть]
...

[➕ Добавить категорию]
```

**Добавление категории:**
1. Бот отправляет новое сообщение: `Введите название категории`.
2. Пользователь вводит название.
3. Бот создает категорию и отправляет карточку новой категории.

Название категории уникально в рамках пользователя.

**Карточка категории:**

```
📂 Еда и напитки

[✏️ Редактировать] [🗑️ Удалить]
```

**Редактирование категории:**
1. Исходная карточка становится неактивной.
2. Бот отправляет новое сообщение: `Введите новое название категории`.
3. После успешного изменения бот отправляет новую актуальную карточку категории.

**Логика удаления:**
1. Проверяем есть ли траты в категории
2. Если **нет** трат → показываем inline-подтверждение на карточке категории и после подтверждения удаляем.
3. Если **есть** траты → бот запускает отдельный пользовательский диалог:

```
По категории «Еда и напитки» есть 12 трат на сумму 8450 ₽.

Что сделать?
[🗑️ Удалить категорию и все траты]
[🔄 Перенести траты в другую категорию]
[❌ Отмена]
```

Если выбран перенос, бот предлагает выбрать целевую категорию через reply-клавиатуру со всеми остальными категориями.

### 4. Добавление расхода (Свободный ввод)
Основной способ — ввод суммы одним сообщением. Описание можно добавить в том же сообщении; бот автоматически отделяет число от текста. Текст становится **описанием**, а категорию пользователь выбирает кнопкой.

**Статус:** реализованный сейчас поток может отличаться от целевого UX. Целевой поток: ввод суммы с опциональным описанием, выбор категории через reply-клавиатуру, выбор даты через reply-клавиатуру или ручной ввод, удаление reply-клавиатуры и отправка отдельной карточки расхода с inline-действиями. Редактирование расхода пока остается планом.

**Логика работы:**
1. **Ввод:** Пользователь пишет `500`, `500 такси` или `обед 450`.
2. **Выбор категории (Reply Keyboard):** Бот парсит сумму и опциональное описание, затем отправляет новое сообщение и показывает reply-клавиатуру с категориями пользователя. Если категорий нет, бот отвечает: `У вас нет ни одной категории. Создайте хотя бы одну, чтобы записывать расходы.` и возвращает пользователя в главное меню.

``` 💰 **500 ₽**
   📝 такси
   Куда запишем?
   Reply keyboard: [Транспорт] [Еда] [Жилье] [Прочее] [❌ Отмена]
   ```

Если описания нет, строка `📝 ...` не показывается.

Категория выбирается по точному названию. Названия категорий уникальны в рамках пользователя. Если пользователь прислал текст, который не совпадает с категорией, бот повторяет выбор категории.

3. **Дата траты:** после выбора категории бот отправляет новое сообщение и предлагает дату траты через reply-клавиатуру:
```
    Когда была трата?
    Reply keyboard: [Сегодня] [Вчера] [Ввести дату вручную] [❌ Отмена]
```
Если выбран ручной ввод, бот просит дату в формате `ДД.ММ.ГГГГ`. Отмена прекращает создание расхода.

4. **Результат:** После выбора даты расход сохраняется. Бот сначала отправляет короткое сообщение `Готово`, которое убирает reply-клавиатуру, затем отправляет отдельную карточку:
```
    ✅ Сохранено!
    💰Сумма: 500 ₽
    📂Категория: Транспорт
    📅Дата: 24.05.2026
    📝Описание: такси
    [✏️ Редактировать] [🗑️ Удалить]
```
Если описания нет, строка `📝Описание: ...` не показывается.
5. При нажатии кнопок под сохраненным расходом:

**При [🗑️ Удалить]:** Бот сначала показывает подтверждение:
```
    ✅ Сохранено!
    💰Сумма: 500 ₽
    📂Категория: Транспорт
    📅Дата: 24.05.2026
    📝Описание: такси

    Точно хотите удалить расход?
    [🗑️ Да, удалить] [❌ Нет]
```
После подтверждения бот удаляет запись и заменяет сообщение на:
  `Расход удален`

**При [✏️ Редактировать] (план):** Бот предлагает выбрать поле для правки:

Исходная карточка становится неактивной:

```
    Эта карточка открыта для редактирования ниже.
```

Затем бот отправляет новое сообщение:

```
    Что изменить?
    Reply keyboard: [💰 Сумма] [📂 Категория] [📅 Дата] [📝 Описание] [❌ Отмена]
```
6. Логика изменения конкретных полей:
* **[💰 Сумма]:** Бот просит: `Введите новую сумму`.
    * Если введено число: обновляет расход и отправляет новую актуальную карточку (п. 4).
    * Если введена ошибка (текст): пишет `❌ Введите только число` и ждет повторный ввод.
* **[📂 Категория]:** Бот показывает reply-клавиатуру со всеми категориями. После выбора новой категории обновляет расход и отправляет новую актуальную карточку.
* **[📅 Дата]:** Бот предлагает быстрые варианты через reply-клавиатуру или ручной ввод.
* **[📝 Описание]:** Бот просит: `Введите новое описание`. Любой присланный текст становится описанием, после чего бот отправляет новую актуальную карточку.

**Общие правила:**
* Любое действие можно отменить кнопкой **[❌ Отмена]**.
* После каждой успешной правки или отмены бот отправляет новую актуальную карточку расхода.
* Старую карточку, с которой началось редактирование, не восстанавливаем.


### 5. Просмотр расходов + редактирование/удаление

**Кнопка:** `📋 Расходы`

**Статус:** пока не реализовано в продукте. Сейчас кнопка отвечает сообщением, что раздел в работе.

Появляется меню настройки

```
Настройка отображения 📋

📅 Период: За месяц
📂 Категория: Все

[Изменить период 🗓] [Изменить категорию 📁]
[🔎 Показать список]
```

Дальше:

* **[Изменить период 🗓]:** Бот выводит список быстрых фильтров кнопками:
```
    Выберите период:
    [📅 День] [📅 Неделя] [📅 Месяц] [📅 Все время]
```
После выбора бот обновляет текст меню «Настройка отображения».

* **[Изменить категорию 📁]:** Бот выводит список всех категорий пользователя с дополнительным выбором всё:
```
    Выберите категорию для фильтра:
    [Все] [Еда] [Транспорт] ...
```
После выбора бот обновляет текст меню и фильтрует будущий список.

**Просмотр списка [🔎 Показать список]:**
После выбора бот отправляет список (максимум 20 записей, с пагинацией при необходимости):

```
📋 Расходы за неделю (4 шт.)

1. 12.03.2026  Еда    450 ₽   обед с коллегами
   [Открыть]

2. 11.03.2026  Транспорт         120 ₽   такси
   [Открыть]

...
[⬅️ Предыдущие 20]   [Следующие 20 ➡️]
```

Список - snapshot. Если расход был изменен или удален после построения списка, сам список не обновляется автоматически.

- **При [Открыть]** бот заново загружает расход из БД и отправляет отдельную актуальную карточку с кнопками `[✏️ Редактировать] [🗑️ Удалить]`.
- Если расход уже удален или недоступен, бот отвечает: `Этот расход уже удален или недоступен.`
- Редактирование и удаление дальше идут через карточку расхода по правилам из раздела 4.

Для MVP в списке нет прямых кнопок `Редактировать` и `Удалить`, чтобы не поддерживать актуальность старого snapshot-сообщения.

**Статус:** пока не реализовано в продукте. Сейчас кнопка отвечает сообщением, что раздел в работе.
